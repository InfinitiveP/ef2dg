# Разработка компонентов

🌐 **Русский** · [English](../../ef2dg_Docs_en/05_Guides/Component%20Development.md)

Компонент — основной способ добавить поведение объекту. Он наследуется от `Component`, получает `Owner` и вызывается через [GameObject](../02_Architecture/GameObject.md) и [Scene](../02_Architecture/Scene.md).

## Минимальный компонент

```csharp
namespace ef2dg
{
    public class HealthComponent : Component
    {
        public int MaxHealth { get; set; } = 100;
        public int CurrentHealth { get; set; } = 100;

        public HealthComponent() { }

        public override void Update(float deltaTime)
        {
            if (CurrentHealth < 0) CurrentHealth = 0;
        }
    }
}
```

После сборки тип автоматически появится в `Inspector → Add Component`, если он:

- находится в загруженной сборке;
- наследуется от `Component`;
- не является `abstract`;
- имеет открытый конструктор без параметров;
- ещё не добавлен на выбранный объект.

Для загрузки JSON текущий `SceneSerializer` ищет тип строго как `ef2dg.<TypeName>`. Компонент в другом namespace редактор увидит через reflection, но сериализатор не восстановит без изменения кода.

## Жизненный цикл

### Start

Вызывается немедленно из `AddComponent`/`AddComponentDynamic`, а не при первом кадре. На этот момент `Owner` уже назначен, но `ParentScene`, соседние компоненты и сериализованные настройки могут быть не готовы.

При загрузке JSON `Start()` вызывается **до** присваивания сохранённых свойств. Поэтому безопасно использовать его для значений, не зависящих от конфигурации, либо только зарегистрировать начальное состояние. Если нужна инициализация после загрузки, используйте ленивый флаг:

```csharp
private bool _initialized;

public override void Update(float deltaTime)
{
    if (!_initialized)
    {
        _initialized = true;
        // Здесь публичные свойства уже восстановлены.
    }
}
```

### FixedUpdate

Вызывается только в Play Mode с фиксированным шагом `1/60` секунды. Здесь должна жить физика и логика, зависящая от стабильного шага. `Scene` пропускает сущности вне зоны камеры, если `AlwaysActive = false`.

### Update

Вызывается один раз за игровой кадр в Play Mode. Используйте `deltaTime` для таймеров и движения, которое не относится к физике. Не изменяйте коллекцию `Scene.Entities` внутри `foreach`; если нужно удаление, используйте индексный цикл с конца либо отложенную очередь.

### Draw

Вызывается каждый кадр и в Edit Mode, и в Play Mode. Метод должен только рисовать и не менять игровое состояние. Камера передаётся аргументом. Некоторые системные компоненты, например `LightComponent`, намеренно ничего не рисуют сами: их обрабатывает отдельный проход `Engine`. Мировые сущности рисуются до освещения и затемняются им; сущности с `IsUI = true` — после него.

### Trigger callbacks

`OnTriggerEnter`, `OnTriggerStay`, `OnTriggerExit` вызываются `PhysicsBody`, когда его AABB пересекает другой объект с `BoxCollider.IsTrigger = true`. Чтобы зона работала:

1. движущийся объект должен иметь `PhysicsBody`;
2. зона должна иметь `BoxCollider` с `IsTrigger = true`;
3. оба объекта должны находиться в одной `ParentScene`;
4. игровая сцена должна обновляться в Play Mode.

`BoxCollider.IsTrigger = false` сейчас не создаёт твёрдое препятствие для `PhysicsBody`; твёрдые столкновения идут через [Tilemap](../03_Modules/Tilemap.md).

## Доступ к владельцу и соседним компонентам

`Owner` назначается движком. Защищённые свойства базового класса сокращают частые обращения:

- `Position` читает/меняет `Owner.Position`;
- `Sprite` возвращает точный `SpriteComponent`;
- `Physics` возвращает точный `PhysicsBody`.

Для других типов используйте `Owner.GetComponent<T>()`. Метод ищет только точный тип. На объекте хранится максимум один экземпляр каждого типа, поскольку компоненты лежат в `Dictionary<Type, Component>`.

Всегда допускайте отсутствие зависимости:

```csharp
public override void Update(float deltaTime)
{
    var audio = Owner.GetComponent<AudioSourceComponent>();
    if (Sprite == null || Physics == null) return;
    // Работа с зависимостями.
}
```

## Свойства, инспектор и JSON

Публичное свойство с setter автоматически появляется в общей панели инспектора, если его тип поддержан. Но отображение и сохранение — разные системы.

| Тип | Инспектор | JSON |
|---|---:|---:|
| `float` | да | да |
| `bool` | да | да |
| `int` | да | да |
| `string` | да | да |
| `Vector2D<float>` | да | да |
| `Vector4D<float>` | да | да |
| `TransitionSettings` | да | да |
| enum | нет | нет |
| список/словарь/объект | нет | нет |
| свойство без setter | нет | нет |
| приватное поле | нет | нет |

Для словаря можно добавить строковый адаптер, как в `SpriteComponent`:

```csharp
public Dictionary<string, float> Values { get; set; } = new();

public string ValuesJson
{
    get => JsonSerializer.Serialize(Values);
    set => Values = JsonSerializer.Deserialize<Dictionary<string, float>>(value) ?? new();
}
```

Тогда `ValuesJson` сохранится как `string`. Чтобы скрыть техническое поле из общей панели инспектора, понадобится добавить его имя в фильтр `InspectorWindow` либо написать специальный интерфейс.

Runtime-ссылки и кэши, которые не должны попасть в уровень, помечайте атрибутом `[SceneTransient]`: такие свойства игнорируются и при сохранении, и при загрузке.

Для настраиваемого перехода достаточно публичного свойства:

```csharp
public TransitionSettings Transition { get; set; } = new TransitionSettings();
```

Инспектор автоматически покажет тип, длительность и цвет, а `SceneSerializer` сохранит настройки. Запуск выполняется через `Engine.Instance.RunTransition` или `RequestSceneTransition`; см. [Переходы между локациями](Переходы%20между%20локациями.md).

## Конструкторы

Можно иметь дополнительные конструкторы для ручного создания в коде, но открытый конструктор без параметров обязателен для редактора и сериализатора:

```csharp
public PhysicsLikeComponent() { }

public PhysicsLikeComponent(float speed)
{
    Speed = speed;
}
```

Не загружайте OpenGL-ресурсы в конструкторе: `Engine.Resources` и контекст могут быть ещё не готовы. Используйте `ResourceManager` в подходящий момент либо храните путь и загружайте лениво.

## Работа со сценой

После помещения сущности в сцену `Owner.ParentScene` должен указывать на неё. Редактор и сериализатор делают это автоматически. Для сущностей, созданных вручную, назначьте ссылку до добавления компонентов, чьи `Start()` используют сцену:

```csharp
var entity = new GameObject
{
    Name = "Chest",
    ParentScene = this,
    Position = new Vector2D<float>(2f, 1f)
};
entity.AddComponent(new SpriteComponent());
Entities.Add(entity);
```

## Работа с PhysicsBody

`PhysicsBody.Map` должна ссылаться на карту текущей сцены. Инспектор назначает её при добавлении, а сериализатор — после восстановления всех компонентов. При ручном создании передайте карту через конструктор или свойство.

`GravityScale > 0` включает платформенную модель с гравитацией и склонами; `GravityScale = 0` подходит для вида сверху. `EnableStepUp` имеет смысл только при положительной гравитации.

## Анимация и управление

Компонент может управлять `SpriteComponent` через `SetFloat`, `SetBool`, `SetTrigger` и `Play`. Имена параметров и состояний — строковые и чувствительны к регистру. Вызов `Play` с отсутствующим состоянием или пустой текстурой молча ничего не делает.

Для управления используйте логическое действие:

```csharp
if (InputManager.IsActionPressed("Interact"))
{
    // Действие компонента.
}
```

Добавление действия в `Project Settings` только сохраняет привязку; компонент всё равно должен её запросить.

## Логи и диагностика

Пишите сообщения через `Console.WriteLine`; они появятся в окне `Console`. Используйте стабильный префикс компонента:

```csharp
Console.WriteLine("[HealthComponent] Entity died.");
```

Не логируйте каждый `Update` — это быстро заполнит консоль и снизит производительность.

## Типичные ошибки

- Нет конструктора без параметров — `Add Component` или загрузка завершатся исключением.
- Компонент не в namespace `ef2dg` — сохранится по имени, но не восстановится текущим сериализатором.
- Инициализация из настроек в `Start()` — при загрузке используются значения по умолчанию.
- Использование неподдерживаемого типа — свойство видно или работает в коде, но исчезает после загрузки.
- Ожидание двух компонентов одного типа — второй заменит первый в словаре.
- `PhysicsBody.Map == null` — физика сразу завершает `FixedUpdate`.
- Изменение списка сущностей внутри прямого `foreach` — возможна ошибка изменения коллекции.
- Игровая логика в `Draw()` — она будет выполняться также в Edit Mode.

## Контрольный список нового компонента

- [ ] Класс публичный, неабстрактный и находится в `namespace ef2dg`.
- [ ] Есть публичный конструктор без параметров.
- [ ] Публичные настройки используют поддерживаемые сериализатором типы.
- [ ] `Start()` не зависит от ещё не восстановленных значений.
- [ ] Все соседние компоненты проверяются на `null`.
- [ ] Физика находится в `FixedUpdate`, остальная логика — в `Update`.
- [ ] `Draw` не меняет состояние.
- [ ] Проверены сохранение, повторная загрузка и работа после `STOP`/повторного `PLAY`.

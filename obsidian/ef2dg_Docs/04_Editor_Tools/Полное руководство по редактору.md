# Полное руководство по редактору

Редактор встроен в запущенный движок и каждый кадр рисуется через Dear ImGui. Он редактирует текущий экземпляр [Scene](../02_Architecture/Scene.md) напрямую: отдельной копии документа, транзакции или автоматического восстановления нет.

## Общая схема работы

1. Запустите проект из каталога `ef2dg`.
2. Загрузите существующий уровень через `File → Open...` (`Ctrl+O`) либо создайте сцену через `File → New Scene` или кнопку `+` в `Scene View`.
3. Выберите сцену во вкладках `Scene View`.
4. Создавайте сущности в `Hierarchy`, добавляйте компоненты в `Inspector`, рисуйте карту через `Tile Palette`.
5. Сохраните сцену через `File → Save` (`Ctrl+S`) или `File → Save As...` (`Ctrl+Shift+S`).
6. Нажмите зелёную кнопку Play по центру меню (`Ctrl+P`) для проверки и её же для возврата к редактированию.

> [!CAUTION]
> **Play Mode не изолирован**
> Play не клонирует сцену. Игровая логика изменяет те же объекты, которые открыты в редакторе. После Stop позиции, удаление сущностей и публичное состояние компонентов остаются изменёнными. Перед проверкой сохраняйте уровень; для возврата загрузите JSON заново.

## Главное меню и раскладка окон

Интерфейс оформлен в стиле VS Code (тема `EditorTheme`, шрифт Segoe UI при наличии в системе, иначе Roboto из `assets/fonts`).

- **Главное меню** (`MainMenuBar`) всегда закреплено у верхнего края окна: `File`, `Edit`, `View`, `Run`, `Help`. По центру — кнопка Play/Stop, справа — имя текущей сцены.
- **Область докинга** (`EditorLayout`) занимает всё окно между меню и строкой состояния. Окна можно перетаскивать за вкладку, стыковать к краям, складывать во вкладки и отрывать в плавающие окна.
- **Закрытие и открытие окон**: крестик в заголовке закрывает окно, `View` показывает список окон с галочками. Видимость окон хранится в `editor_layout.json`, положение и стыковка — в `imgui.ini`.
- **Раскладка по умолчанию** (`View → Reset Layout`): слева `Hierarchy` и `Asset Browser`, по центру `Scene View`, справа `Inspector` и `Lighting`, снизу `Console`, `Tile Palette`, `Project Settings`. Она же применяется при первом запуске новой версии раскладки (`EditorLayout.CurrentLayoutVersion`).
- **Строка состояния** внизу: синяя в режиме редактирования и оранжевая в Play Mode; показывает сцену, число сущностей, выбранный объект, инструмент, камеру, масштаб и FPS.
- **Escape** движок не перехватывает: в редакторе он закрывает меню и диалоги, в Play Mode свободен для биндов игры. Выход — `File → Exit` или `Alt+F4`.

Горячие клавиши: `Ctrl+S`, `Ctrl+Shift+S`, `Ctrl+O`, `Ctrl+Z`/`Ctrl+Y`, `Ctrl+P`, `Ctrl+Shift+N`; полный список — `Help → Keyboard Shortcuts`. Пока активно поле ввода, сочетания с `Ctrl` и движение камеры WASD не срабатывают.

## Команды File, Edit и Run

Те же действия доступны в окне `Toolbar` (по умолчанию скрыто, включается в `View`).

### Play и Stop

Play сохраняет текущий редакторский `Camera.Zoom` в `EditorCameraZoom`, применяет `ProjectConfig.Data.DefaultCameraZoom` и разрешает `FixedUpdate`/`Update`. Stop выключает игровое обновление и возвращает редакторский масштаб. Аудио при выходе из Play Mode ставится на паузу, при возвращении продолжается.

### Undo и Redo

История команд содержит только `PaintTileCommand`. В неё попадают покраска и стирание клетки, выполненные в `Scene View`. Переименование, transform, добавление/удаление сущности или компонента, настройки тайла и загрузка уровня в историю не входят.

Новая команда после Undo очищает стек Redo. История общая для `EditorState`, поэтому не привязана явно к конкретной вкладке сцены.

### Save и Save As

`Save` записывает сцену в файл, из которого она загружена или в который сохранена последней (`Scene.FilePath`). Если сцена ещё не сохранялась, открывается `Save As`.

В `Save As` поле имени автоматически получает расширение `.json`. При подтверждении имя без расширения записывается в `Scene.InstanceName`, после чего [SceneSerializer](../03_Modules/SceneSerializer.md) сохраняет текущую сцену. Подтверждения перезаписи и проверки несохранённых изменений нет.

Файл создаётся относительно текущего рабочего каталога. Рекомендуется использовать простые уникальные имена без путей и всегда запускать редактор из `ef2dg`.

### Open

Список строится из всех `*.json` в рабочем каталоге, кроме служебных: `bindings.json`, `level_backup.json`, `project_config.json`, `lighting_presets.json`, `editor_layout.json`. Двойной клик открывает файл сразу.

Загрузчик читает `SceneType` и `InstanceName`. Если в `OpenedScenes` уже есть сцена с подходящим именем и типом, её экземпляр переиспользуется, старые сущности очищаются и заменяются содержимым файла. Иначе тип ищется как `ef2dg.<SceneType>`; при неудаче создаётся `GameScene`.

## Scene View и вкладки сцен

Первая активная сцена автоматически добавляется в `OpenedScenes`. Кнопки вкладок меняют контекст через `Engine.ChangeScene`. Контекстное меню вкладки позволяет менять `InstanceName`; крестик закрывает вкладку без сохранения и без подтверждения. Последнюю вкладку закрыть нельзя.

Кнопка `+` показывает все неабстрактные классы-наследники `Scene` из текущей сборки. Для новой `GameScene` редактор сразу ставит `IsLoadedFromFile = true`, чтобы не создавать стандартного игрока. Из-за раннего выхода в `GameScene.Load` такая сцена может остаться без `Tilemap`; практически безопаснее создавать новый уровень из корректного JSON-шаблона.

### Навигация и выбор

- Колесо мыши над viewport меняет `Zoom` на 10% текущего значения; диапазон `0.1–20`.
- Двойной клик по сущности в `Hierarchy` переносит камеру к ней.
- В режиме `Select` левый клик выбирает сущность, перебирая список с конца: визуально более поздний объект имеет приоритет.
- Для обычной сущности область выбора строится вокруг `Position` по `Scale`.
- Для `ButtonComponent` координаты и `Size` считаются экранными пикселями от левого верхнего угла viewport.
- Перетаскивание меняет позицию напрямую. У `PhysicsBody` скорость при этом сбрасывается.

### Инструменты карты

`Paint` записывает выбранный путь текстуры в клетку активного слоя, `Erase` записывает пустую строку. Координата клетки вычисляется из мировых координат и `TileSizeInWorld`. Кисть подсвечивается только в Edit Mode.

## Hierarchy

`Create Empty GameObject` создаёт объект в `(0, 0)`, назначает `ParentScene`, имя `Entity N` и добавляет его в конец `Entities`.

Иконки справа от имени (рисуются `EditorIcons`): стрелки вверх и вниз меняют порядок в списке, корзина удаляет сущность. Порядок влияет на отрисовку и выбор мышью: сущности рисуются по списку, а выбираются в обратном порядке. Удаление происходит сразу; lifecycle-метода очистки и Undo нет. Иконки приглушены, пока строка не под курсором и не выбрана.

## Inspector

В верхней части редактируются `Name`, `IsUI`, `AlwaysActive`, `Position`, `Scale` и `Rotation`. Далее показываются все компоненты объекта.

Обычная reflection-панель поддерживает публичные свойства с setter типов:

- `float` — `DragFloat` с шагом `0.1`;
- `bool` — checkbox;
- `int` — `DragInt`;
- `Vector2D<float>` — два float;
- `Vector4D<float>` — выбор цвета;
- `string` — строка до 256 символов.

Показ свойства в инспекторе не гарантирует сохранение: JSON поддерживает более узкий набор, см. [Формат уровня и сериализация](../03_Modules/Формат%20уровня%20и%20сериализация.md). Вычисляемые свойства без setter не редактируются. `AnimationsJson`, `ParametersJson`, `SoundClipsJson`, `DefaultSoundPath`, `FrameWidth` и `AnimationSpeed` скрыты из общей панели, потому что для них есть специальные интерфейсы.

### Добавление и удаление компонентов

`Add Component` перечисляет все неабстрактные наследники `Component` в текущей сборке. Тип, который уже есть на объекте, не показывается. Создание идёт через `Activator.CreateInstance`, поэтому нужен публичный конструктор без параметров.

При добавлении `PhysicsBody` редактор отдельно назначает карту текущей сцены и начальный `HitboxSize = (0.5, 0.5)`. Для остальных компонентов дополнительной настройки нет. `Start()` вызывается немедленно. Удаление выполняется без подтверждения и без метода `Dispose`/`OnRemoved`.

### SpriteComponent

Панель показывает обнаруженные параметры аниматора, состояния, текстуру, `FrameWidth`, скорость, зацикливание, звуковые события и переходы. Имена состояний и целевых состояний чувствительны к регистру. `FrameWidth` должен делить ширину sprite sheet ожидаемым образом; число кадров вычисляется как целочисленное `Texture.Width / FrameWidth`.

Правила переходов проверяются по порядку списка текущего состояния, срабатывает первое подходящее. Поддерживаются операторы `>`, `<`, `>=`, `<=`, `==`, `!=`; специальный `ParameterName = ExitTime` срабатывает после завершения незакольцованной анимации. Trigger сбрасывается после принятого перехода.

Звуковое событие связывает номер кадра с ключом `AudioSourceComponent.SoundClips`, а не напрямую с файлом.

### AudioSourceComponent

Можно выбрать основной трек, проверить его кнопками Play/Stop и создать словарь SFX-ключей. Интерфейс показывает WAV, OGG и MP3, но текущий `AudioEngine` декодирует только PCM WAV. Для гарантированной работы выбирайте `.wav`.

`PlayOnStart` означает первый `Update` компонента в Play Mode. Флаг не сбрасывается автоматически при `STOP`; повторный запуск той же сцены может не перезапустить звук, пока код явно не вызовет `ResetPlayState`.

### Настройки перехода

Если компонент содержит публичное свойство `TransitionSettings`, инспектор показывает вложенную группу с `Effect`, `Duration` и `Color`. Сейчас такая группа есть у `ButtonComponent` и `TeleportTriggerComponent`. Настройки сохраняются в JSON; подробности приведены в [Переходы между локациями](../05_Guides/Переходы%20между%20локациями.md).

## Tile Palette

Режимы `Select`, `Paint`, `Erase` общие со `Scene View`. Активный слой выбирается из `Map.Layers`; `Layer Physics Enabled` разрешает карте учитывать слой при столкновениях.

Палитра показывает только PNG непосредственно в `assets/Tiles`, без рекурсивного обхода подпапок. Через `Asset Browser` можно дважды щёлкнуть PNG из любой подпапки и назначить его кистью.

Настройки привязаны к пути текстуры и общие для всех клеток с этим путём в текущей карте:

- `Texture Scale` и `Texture Offset` меняют размер и положение изображения;
- `Frame Count` и `Anim Speed` задают горизонтальную sprite-sheet анимацию;
- `Flip X/Y` отражают UV;
- `Tile Collision` выбирает `None`, `Solid`, `SlopeLeft`, `SlopeRight`;
- `Hitbox Scale/Offset` доступны только для `Solid`; склоны всегда совпадают с сеткой.

## Asset Browser и импорт

Окно рекурсивно показывает содержимое `assets`. Один клик выбирает файл и делает его родительскую папку текущей целью импорта. Двойной клик по PNG включает кисть тайлов. PNG получает предпросмотр; WAV/MP3 — кнопки Play/Stop; JSON помечается как файл сцены.

Перетаскивание внешних файлов обрабатывает `Engine.FileDrop`: каждый файл копируется в `CurrentAssetFolder` с `overwrite = true`. Диалога подтверждения нет, структура исходных папок не переносится, импорт метаданных не выполняется.

## Project Settings

Окно изменяет `DefaultCameraZoom` и `BackgroundColor`, сохраняя их в `project_config.json`. Освещение настраивается для каждой сцены отдельно в окне **Lighting** (см. [Освещение](../05_Guides/Освещение.md)). Здесь же редактируется `InputManager.Bindings`: можно ожидать следующую нажатую клавишу и добавлять новые действия.

Новые действия появляются в JSON, но сами по себе ничего не делают — компонент должен запрашивать их через `InputManager.IsActionPressed`.

## Console

`ConsoleInterceptor` перехватывает `Console.Write`/`WriteLine` и хранит строки для окна `Console`. Кнопка `Clear` очищает видимую историю, `Auto-scroll` прокручивает к новым сообщениям. Цвет определяется подстроками `ERROR`, `Failed`, `WARNING`, `EVENT` и русскими аналогами; это визуальная эвристика, а не уровни структурированного логгера.

## Рекомендуемый безопасный цикл

1. Загрузить или создать корректную сцену.
2. Внести одно логическое изменение.
3. Сохранить JSON.
4. Запустить Play Mode и проверить Console/F1–F5.
5. Нажать Stop и повторно загрузить JSON, если рантайм изменил сцену.
6. Перед закрытием вкладки снова сохранить результат.

# Component

`Component` — базовый абстрактный класс поведения. После добавления к [GameObject](GameObject.md) свойство `Owner` указывает на владельца. Для удобства доступны защищённые `Position`, `Sprite` и `Physics`.

## Жизненный цикл

`AddComponent` и `AddComponentDynamic` назначают `Owner` и сразу вызывают `Start`. Затем сцена вызывает `FixedUpdate`, `Update` и `Draw` через объект-владельца. Триггерная физика вызывает `OnTriggerEnter`, `OnTriggerStay` и `OnTriggerExit`.

Публичные изменяемые свойства типов `float`, `bool`, `int`, `string` и `Vector2D<float>` сериализуются [SceneSerializer](../03_Modules/SceneSerializer.md). Сложные или только вычисляемые поля требуют отдельной поддержки сериализации.

## Важные особенности

- На одном `GameObject` может быть только один компонент каждого точного типа: словарь использует `Type` как ключ.
- `GetComponent<T>()` ищет точное совпадение типа, а не любой класс-наследник.
- `Start()` вызывается сразу при добавлении компонента. Во время загрузки JSON это происходит **до** присваивания сохранённых свойств.
- Компонент, создаваемый через редактор или загрузчик, обязан иметь открытый конструктор без параметров.
- Не следует полагаться на порядок выполнения разных компонентов: он определяется содержимым внутреннего словаря.
- Удаление компонента не вызывает отдельного метода завершения — такого lifecycle hook сейчас нет.

Полный шаблон и правила разработки приведены в [Разработка компонентов](../05_Guides/Разработка%20компонентов.md).

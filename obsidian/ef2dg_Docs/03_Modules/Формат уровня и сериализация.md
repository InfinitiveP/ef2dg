# Формат уровня и сериализация

🌐 **Русский** · [English](../../ef2dg_Docs_en/03_Modules/Level%20Format%20and%20Serialization.md)

Уровень — JSON-представление [Scene](../02_Architecture/Scene.md), формируемое [SceneSerializer](SceneSerializer.md). Файл читается относительно рабочего каталога.

## Верхний уровень

```json
{
  "SceneType": "GameScene",
  "InstanceName": "level_1",
  "Entities": [],
  "TileLayers": [],
  "TileConfigs": {},
  "Lighting": {}
}
```

- `SceneType` — имя класса сцены без namespace.
- `InstanceName` — имя экземпляра и подпись вкладки редактора.
- `Entities` — сущности и компоненты.
- `TileLayers` — слои и клетки карты.
- `TileConfigs` — настройки, общие для каждого пути текстуры.
- `Lighting` — настройки освещения сцены, см. [Освещение](../05_Guides/Освещение.md).
- `TextureScales` — устаревшее поле совместимости, используемое только если `TileConfigs` пуст.

## Сущность

`EntityData` сохраняет имя, transform, `AlwaysActive` и `IsUI`. Поэтому UI-сущности и системные объекты сохраняют режим экранного слоя и обновление вне simulation zone после повторной загрузки.

## Компонент

Каждый `ComponentData` хранит `TypeName` и словари значений по типам. Имя компонента должно разрешаться через `Type.GetType("ef2dg.<TypeName>")`. Переименование класса ломает загрузку старых уровней: неизвестный компонент будет пропущен без миграции данных.

## Матрица поддержки

| Данные | Сохраняются | Примечание |
|---|---:|---|
| `float`, `bool`, `int`, `string` | да | публичное свойство с setter |
| `Vector2D<float>` | да | массив из двух чисел |
| `Vector4D<float>` | да | массив из четырёх чисел в `VectorValues` |
| `Scene.Lighting` | да | поле `Lighting` уровня; при отсутствии берётся legacy-настройка `project_config.json`, см. [Освещение](../05_Guides/Освещение.md) |
| `TransitionSettings` | да | отдельный `TransitionValues` с видом, длительностью и RGBA |
| enum | нет | нужен int/string-адаптер |
| массив, список, словарь | нет | нужен JSON-string адаптер |
| приватное поле | нет | рантайм-состояние теряется |
| `GameObject.IsUI` | да | поле `EntityData.IsUI` |
| `GameObject.AlwaysActive` | да | поле `EntityData.AlwaysActive`, редактируется в Inspector |
| `ParentScene`, `Owner`, `Map` | восстанавливаются кодом | не сериализуются напрямую |
| свойство с `[SceneTransient]` | нет | игнорируется и при сохранении, и при загрузке; предназначено для runtime-ссылок и кэша |

## Порядок восстановления

Сцена очищает старые сущности. Карта пересоздаёт слои и конфигурации. Затем для каждой сущности создаются компоненты, причём `Start()` вызывается до заполнения свойств. После этого `PhysicsBody.Map` привязывается к карте, `SpriteComponent` запускает анимацию и игрок назначается в `GameScene.Player`.

Следствия:

- `Start()` видит значения по умолчанию;
- ссылки между сущностями не сохраняются;
- приватные таймеры и кэш сбрасываются;
- runtime-ресурсы надо восстанавливать лениво;
- runtime-ссылки, например созданный во время запуска `ProfileId`, должны иметь `[SceneTransient]`, иначе сохранение в Play Mode загрязнит данные уровня;
- порядок сущностей сохраняется списком, порядок компонентов не следует считать контрактом.

## Совместимость файлов

Добавление нового публичного свойства безопасно: старый JSON оставит значение по умолчанию. Удаление или переименование свойства оставит старое поле в JSON, но оно не будет применено. Переименование класса компонента или `SceneType` требует миграции либо совместимого класса со старым именем.

## Проверка нового компонента

1. Добавьте компонент через Inspector.
2. Измените все сохраняемые свойства на отличимые значения.
3. Сохраните уровень.
4. Закройте или очистите текущую сцену.
5. Загрузите JSON.
6. Проверьте свойства, зависимости и поведение первого кадра.
7. Откройте JSON вручную и убедитесь, что сложные данные действительно записаны.

# SceneSerializer

🌐 **Русский** · [English](../../ef2dg_Docs_en/03_Modules/SceneSerializer.md)

`SceneSerializer.Save(scene, filePath)` создаёт [LevelData](LevelData.md) и записывает форматированный JSON. `Load(scene, filePath, resources)` читает JSON и возвращает `false`, если файл отсутствует, пуст или не разбирается.

При загрузке очищаются сущности и данные карты, восстанавливаются слои и конфигурация тайлов, затем создаются компоненты. Для `PhysicsBody` назначается текущая карта; для `SpriteComponent` запускается `Idle` либо первая анимация; игрок `GameScene` определяется по `PlayerController`.

Сериализатор не сохраняет OpenGL-ресурсы, делегаты, приватное состояние, UI-состояние редактора и неподдерживаемые типы свойств.

## Поддерживаемые свойства компонентов

Автоматически сохраняются только публичные свойства с публичным setter типов `float`, `bool`, `int`, `string`, `Vector2D<float>` и `Vector4D<float>` (векторы — в `VectorValues`, `Vector4D` как массив из четырёх чисел). Настройки освещения сцены сохраняются в поле `Lighting` уровня; у старых уровней без этого поля они берутся из `project_config.json` (см. [Освещение](../05_Guides/Освещение.md)).

Словари анимаций и аудио сохраняются обходным путём через строковые свойства `AnimationsJson`, `ParametersJson` и `SoundClipsJson`. Для нового сложного типа нужен такой же сериализуемый адаптер либо расширение `ComponentData`.

## Порядок загрузки

1. Создаётся компонент через `Activator.CreateInstance`.
2. `AddComponentDynamic` назначает `Owner` и вызывает `Start()`.
3. Только после этого сериализатор присваивает свойства из JSON.

Поэтому `Start()` не должен окончательно вычислять состояние из сохраняемых настроек. Инициализацию, зависящую от загруженных значений, нужно делать лениво в первом `Update`, отдельным методом после загрузки либо после будущего расширения lifecycle.

Подробнее: [Формат уровня и сериализация](Формат%20уровня%20и%20сериализация.md).
